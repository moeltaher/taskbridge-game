# No Boss

**الإصدار الحالي: v3.8.0 · نموذج الدرجة 9 · النموذج الاقتصادي 4**

لعبة ومحاكاة تدريبية عربية لفهم اقتصاد المنصات، والإدارة الخوارزمية، وتوزيع السلطة والأعباء، وشروط العمل، والوصول إلى الفرص في العمل الرقمي.

## ما تغير في المراجعة الحالية

- خريطة السلطة والعبء أصبحت ترتيبًا نوعيًا واضحًا: دور رئيسي، دور ثانوي، أو لا دور. أزيلت النسب المئوية والتعبئة التلقائية التي كانت توحي بدقة لا تستخدمها الدرجة.
- محور العبء يقيس من تحمّل فعليًا التكاليف والمخاطر والوقت غير المدفوع، ولا يمنح المنصة أو العميل وزنًا لمجرد مساهمتهما في تصميم الخطر.
- سلطة الحساب والوصول العام إلى السوق فُصلت عن سلطة العميل داخل مشروع بعينه؛ اختيار العميل أو استبعاده للعامل داخل مشروع يظهر في توزيع الفرص، لا في إدارة الحساب العام.
- أصبح ترتيب الفرص يستخدم جودة الحساب المتراكمة بعد أن تحدّثها نتيجة المهمة، بدل إعادة استخدام نتيجة المهمة الخام كعامل مستقل.
- كل قرار على العرض الثاني يضيف دقيقتين إلى وقت السوق/البحث: القبول والرفض وإنهاء الوردية دون رفض.
- أصبحت حدود مراجعة الجودة معلنة، وكذلك كلفة طلب المراجعة الثانية قبل اتخاذ القرار.
- الأسئلة التشخيصية موصوفة بوضوح بأنها إلزامية للانتقال وغير محسوبة في الدرجة.
- الاستنتاج النهائي لم يعد يقبل عددًا اعتباطيًا من الأدلة أو حدًا شكليًا لطول النص؛ يجب دعم ادعاء الوصول بدليل وصول/عقد، وادعاء العبء بدليل عبء عندما يكون مطلوبًا.
- أضيف وضع للميسّر يسمح بفرض حدث خطر مؤهل أو منع الحدث الإضافي من أجل التدريب الجماعي والمقارنة بين المسارات.
- وُضّح أساس رسوم وسيط الدفع في النموذج الاقتصادي: النسبة تحسب على المقابل المتفق عليه قبل فصل الرصيد المحجوز.
- `STATE_SCHEMA_VERSION=10` و`SCORE_MODEL_VERSION=9` و`ECONOMY_MODEL_VERSION=4`. لا تُهاجر الحالات القديمة ولا تُعرض نتائج نماذج سابقة داخل النموذج الحالي.
- أضيف فحص عام للكود الميت يفشل إذا بقي module JavaScript في runtime لا تصل إليه أي صفحة أو نقطة دخول حالية.

## المسارات الحالية

`/scenario/`, `/onboarding/`, `/work/`, `/management/`, `/risk/`, `/dispute/`, `/payment/`, `/access/`, `/investigation/`, `/power/`, `/conclusion/`, `/result/`, `/rights/`.

ملفات HTML لهذه المسارات مولدة ومطلوبة لـGitHub Pages وليست صفحات قديمة. المصدر الوحيد للمسارات هو `assets/js/core/routes.js`، والمولد يرفض الانحراف ويحذف أي route shell مولد يصبح يتيمًا.

## سياسة الإصدارات السابقة

لا توجد طبقة migration للحالات القديمة في runtime. الحالة المحفوظة تُقبل فقط إذا كانت schema الحالية، ونتائج الأرشيف تُعرض فقط إذا كانت من نموذج الدرجة والنموذج الاقتصادي الحاليين. أزيلت fallbackات `legacy` وكود تحويل خرائط السلطة أو التسويات القديمة.

لا يعني ذلك حذف مكونات حية مثل `core/storage.js` أو `scripts/serve-static.mjs` أو route shells؛ هذه مستخدمة فعليًا في التشغيل والاختبارات والنشر.

## التحقق قبل النشر

```bash
npm run check
npm run test:e2e
```

يتضمن `npm run check` فحص المسارات والبنية والانحدارات ومنطق المجال والثوابت الدلالية والكود الميت وصحة JavaScript.

## ملاحظة قانونية

المحاكاة أداة تدريبية لتحليل الوقائع وتوزيع وظائف السيطرة والأعباء، وليست حكمًا قانونيًا نهائيًا على توصيف علاقة العمل.
