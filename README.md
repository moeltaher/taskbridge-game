# No Boss

**الإصدار الحالي: v3.2.0**

لعبة ومحاكاة تدريبية عربية لفهم اقتصاد المنصات، والإدارة الخوارزمية، وتوزيع السلطة والأعباء، وشروط العمل، والوصول إلى الفرص في العمل الرقمي.

تضع اللعبة اللاعب داخل منصة افتراضية اسمها **No Boss**، ثم تنقله من تجربة العامل إلى دور الباحث. ويمكن أن تنتهي التجربة بورديّة عمل، أو مغادرة السوق دون قبول مهمة، أو رفض شروط الدخول ثم تحليل بوابة العقد نفسها.

المشروع تطبيق ثابت متعدد الصفحات يعمل على GitHub Pages، من دون backend أو API أو قاعدة بيانات أو إطار عمل مثل React/Vue.

راجع [CHANGELOG.md](CHANGELOG.md) لتاريخ الإصدارات و[ARCHITECTURE.md](ARCHITECTURE.md) لتفاصيل البنية.

## ما تغير في v3.2

- فصل **السلطة/التحكم** عن **تحمل التكاليف والمخاطر** في خريطة التحليل.
- منع مسار عدم العمل من تقييد «مشروع حالي» لم يقبله العامل أصلًا.
- جعل وقوع أحداث المخاطر ثابتًا داخل الجولة وغير متأثر بقرارات لا علاقة سببية لها بالحادث.
- عدم إنشاء دليل حادث عندما لا يقع حادث فعلي.
- اشتقاق الرسم والـground truth لمهمة تصنيف الصور من مصدر هندسي واحد.
- جعل المسار غير البصري يقدّر الموضع والحجم بدل منحه أبعاد الإجابة الصحيحة تلقائيًا.
- إظهار دليل أسلوب الترجمة قبل تنفيذ المهمة.
- فصل معيار الجودة عن المراقبة كبعد تحليلي مستقل.
- اعتبار سؤال تحديد الأطراف سؤالًا تمهيديًا غير محسوب في الدرجة.
- تسمية النتيجة الرقمية **درجة التوافق مع المرجع التدريبي** بدل الإيحاء بأنها تقييم كامل لجودة الحجة.
- السماح للدليل بأن يدعم الاستنتاج ويعقده في الوقت نفسه.
- إضافة مسار بحثي لرفض شروط الحساب.
- شرح منطق المرجع لكل محور في صفحة النتيجة.
- إظهار حدود الانتصاف المتأخر عندما ينجح الاعتراض بعد فوات فرصة سابقة.
- إظهار وقت السوق/البحث في جميع تفصيلات الزمن، وإظهار نتيجة اقتصادية صفرية لمسار عدم العمل.
- توضيح أن تكاليف التشغيل أرقام تقديرية ثابتة للوردية التدريبية.
- إصدار نتائج الأرشيف بحسب `scoreModelVersion` حتى لا تقارن درجات من نماذج تقييم مختلفة.

## بنية الصيانة

- `assets/js/core/` — الحالة، التخزين، المسارات، الواجهة، ونموذج الدرجة.
- `assets/js/domain/` — قواعد العمل، الإدارة، المخاطر، الاعتراض، الدفع، الوصول والتحليل.
- `assets/js/data/` — السيناريوهات، الأطراف، نموذج السلطة، مبررات المرجع، عينات العمل وهندسة مشاهد البيانات.
- `assets/js/pages/` — واجهات مراحل اللعبة.
- `assets/css/` — التصميم والاستجابة.
- `tests/e2e/` — اختبارات Playwright والوصول.

ملفات HTML الخاصة بالمسارات مولدة من route manifest. بعد تغيير عنوان أو مسار أو إصدار:

```bash
node scripts/generate-pages.mjs
```

## التحقق قبل النشر

```bash
npm run check
npm run test:e2e
```

وتشمل الفحوص غير المتصفحية:

```bash
npm run check:routes
npm run check:structural
npm run check:regression
npm run check:domain
npm run check:semantic
npm run check:syntax
```

`check:semantic` يختبر سلوك النموذج بين المكونات، بما في ذلك منع تقييد مشروع غير موجود، وثبات المخاطر أمام الخيارات غير السببية، وفصل الجودة عن المراقبة، وتكافؤ مساري مهمة البيانات، واستبعاد السؤال التمهيدي من الدرجة.

اختبارات المتصفح تعمل على Chromium وWebKit في إعدادات سطح المكتب والموبايل، وتشمل فحوص وصول آلية باستخدام axe إضافة إلى اختبارات لوحة المفاتيح والمسارات الأساسية.

## ملاحظة قانونية

المحاكاة أداة تدريبية لتحليل الوقائع وتوزيع وظائف السيطرة والأعباء، وليست حكمًا قانونيًا نهائيًا على توصيف علاقة العمل.
