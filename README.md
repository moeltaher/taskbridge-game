# No Boss

**الإصدار الحالي: v3.3.0**

لعبة ومحاكاة تدريبية عربية لفهم اقتصاد المنصات، والإدارة الخوارزمية، وتوزيع السلطة والأعباء، وشروط العمل، والوصول إلى الفرص في العمل الرقمي.

تضع اللعبة اللاعب داخل منصة افتراضية اسمها **No Boss**، ثم تنقله من تجربة العامل إلى دور الباحث. ويمكن أن تنتهي التجربة بورديّة عمل، أو دخول السوق دون قبول مهمة، أو رفض شروط الدخول ثم تحليل بوابة العقد نفسها.

المشروع تطبيق ثابت متعدد الصفحات يعمل على GitHub Pages، من دون backend أو API أو قاعدة بيانات أو إطار عمل مثل React/Vue.

راجع [CHANGELOG.md](CHANGELOG.md) لتاريخ الإصدارات و[ARCHITECTURE.md](ARCHITECTURE.md) لتفاصيل البنية.

## ما تغير في v3.3

- أصبحت «السلطة المشتركة بين المنصة والعميل» نتيجة مرجعية فعلية عندما يكون تأثير الطرفين متقاربًا، بدل أن تكون خيارًا لا يمكن للنموذج إنتاجه.
- فُصل وسيط الدفع عن أطراف سلطة علاقة العمل؛ يظهر في التدفق المالي فقط ما دام لا يقرر السعر أو التوزيع أو الجودة أو الوصول.
- أصبحت خريطة السلطة خريطة نسبية من 100 نقطة بين العامل والمنصة والعميل، مع تقييم ترتيب القوة بدل مطابقة نسب مخفية.
- أصبح الأرشيف يقارن فقط بين جولات الشخصية نفسها ومسار النهاية نفسه ونموذج الدرجة نفسه.
- دخول سوق المهام دون قبول عمل يحمّل تكاليف التشغيل المقدرة، لكنه لا يفرض رسوم تحويل أو وسيط دفع لعدم وجود مبلغ محول.
- رفض شروط الحساب ثم إعادة النظر لا يمحو الرفض السابق؛ يبقى كسجل واقعة ويضاف قرار إعادة النظر والقبول اللاحق.
- اعتراض مهام تعليم البيانات أصبح يعتمد على الانحراف الفعلي في الإجابة، ولا يقبل سببًا تقنيًا من مجرد انخفاض الدرجة دون عطل مسجل.
- أضيف دليل موحد وواضح قبل المهمة الأولى والثانية، بما في ذلك تعريفات فئات مراجعة المحتوى وتعليمات طريقة الرسم والبديل غير البصري.
- المهمة الثانية تستخدم حالة اختيار قابلة للإعلان لتقنيات المساعدة عبر `aria-pressed`.
- لم يعد الاستنتاج يفرض «دليلًا مضادًا» لمجرد توفر ثلاثة أدلة؛ يطلب دليلًا مقيدًا أو مزدوجًا فقط عندما يراه اللاعب متسقًا مع الوقائع.
- رُفع مخطط الحالة إلى `STATE_SCHEMA_VERSION=4` وحُذفت حقول قديمة لم تعد جزءًا من النموذج: `marketExit`, `powerDraft`, `powerEdited`, `qualityAfterFirstTask`, `reviewTaskScore`, `realFinishedAt`.
- حُذفت دالة `distributionProximity` القديمة لأن نموذج الدرجة الحالي لا يستخدم قرب النسب الرقمية.
- أصبح مولد صفحات المسارات يكتشف قواقع HTML المولدة التي لم تعد موجودة في route manifest ويبلغ عنها/يحذفها عند التوليد.
- توسعت الاختبارات لتغطي اقتصاد مسار عدم العمل، إعادة النظر في العقد، السلطة المشتركة، الاعتراض القائم على الوقائع، وحالة الوصول في المهمة الثانية.

## الروابط المنطقية

`/scenario/`, `/onboarding/`, `/work/`, `/management/`, `/risk/`, `/dispute/`, `/payment/`, `/access/`, `/investigation/`, `/power/`, `/conclusion/`, `/result/`, `/rights/`.

هذه ملفات HTML مولدة ومطلوبة لـGitHub Pages؛ منطق اللعبة لا يتكرر داخلها. المصدر الوحيد للمسارات هو `assets/js/core/routes.js`.

## بنية الصيانة

- `assets/js/core/` — الحالة، التخزين، المسارات، الواجهة، ونموذج الدرجة.
- `assets/js/domain/` — قواعد العمل، الإدارة، المخاطر، الاعتراض، الدفع، الوصول والتحليل.
- `assets/js/data/` — السيناريوهات، الأطراف، نموذج السلطة، أدلة المهام، العينات وهندسة مشاهد البيانات.
- `assets/js/pages/` — واجهات مراحل اللعبة.
- `assets/css/` — التصميم والاستجابة.
- `tests/e2e/` — اختبارات Playwright والوصول.

بعد تغيير عنوان أو مسار أو إصدار:

```bash
node scripts/generate-pages.mjs
```

## التحقق قبل النشر

```bash
npm run check
npm run test:e2e
```

`npm run check` يغطي تطابق route manifest، البنية، ترحيل الحالة والتخزين، قواعد المجال، الاتساق بين الوحدات، وصحة JavaScript. اختبارات المتصفح تعمل على Chromium وWebKit لسطح المكتب والموبايل وتضم فحوص axe على الصفحات المهمة ومسارات الاختيار القابلة للوصول.

## ملاحظة قانونية

المحاكاة أداة تدريبية لتحليل الوقائع وتوزيع وظائف السيطرة والأعباء، وليست حكمًا قانونيًا نهائيًا على توصيف علاقة العمل.
