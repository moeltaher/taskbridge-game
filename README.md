# No Boss

**الإصدار الحالي: v3.4.0**

لعبة ومحاكاة تدريبية عربية لفهم اقتصاد المنصات، والإدارة الخوارزمية، وتوزيع السلطة والأعباء، وشروط العمل، والوصول إلى الفرص في العمل الرقمي.

تضع اللعبة اللاعب داخل منصة افتراضية اسمها **No Boss**، ثم تنقله من تجربة العامل إلى دور الباحث. ويمكن أن تنتهي التجربة بورديّة عمل، أو دخول السوق دون قبول مهمة، أو رفض شروط الدخول ثم تحليل بوابة العقد نفسها.

المشروع تطبيق ثابت متعدد الصفحات يعمل على GitHub Pages، من دون backend أو API أو قاعدة بيانات أو إطار عمل تطبيقات.

## ما تغير في v3.4

- أصبح زر الرجوع يعيد الحالة إلى ما قبل القرار الذي نقل اللاعب إلى المرحلة التالية؛ فلا يمكن الرجوع من نهاية «بلا عمل» مع بقاء `noWorkEnding`، ولا تكرار أثر الاستراحة عبر الرجوع من صفحة المخاطر.
- أصبح `commit/patch` يقبلان فقط مفاتيح مخطط الحالة الحالي، فلا تستطيع أكواد قديمة إعادة إدخال حقول محذوفة.
- ارتفع `STATE_SCHEMA_VERSION` إلى 5 وحُذفت بقايا الحالة القديمة: `initialStress`, `firstTaskStress`, `secondTaskScore`, `disputeSeverity`, `disputedTaskPay`، بالإضافة إلى الحقول التي حُذفت في الإصدارات السابقة.
- استُبدل مرجع السلطة ذي النسب اليدوية بمرجع رتبي صريح: طرف/أطراف أساسية ثم أطراف ثانوية. تبقى 100 نقطة في واجهة الخريطة أداة رسم للمشارك فقط.
- أصبحت أسئلة علاقة العمل تشخيصية وغير محسوبة، وأصبحت الدرجة 40 نقطة لتصنيف الأدلة و60 لخريطة السلطة والعبء (`SCORE_MODEL_VERSION=4`).
- أضيف سؤال مستقل عن التسوية المالية في المسار الكامل حتى لا يختلط دور وسيط الدفع بسلطة إدارة العمل.
- أضيف خيار إنهاء الوردية بعد المهمة الأولى دون رفض العرض الثاني أو تغيير معدل القبول.
- وُحّدت واجهة تنفيذ المهمة الأولى والثانية في `assets/js/core/task-ui.js` بدل وجود نسختين متوازيتين للرسم والاختيارات والتعليمات.
- أصبحت آثار مراجعة المحتوى مرتبطة بالعينات التي ظهرت فعلًا، وأصبح العطل التقني في سيناريو البيانات واقعة مسجلة يمكن أن تسند اعتراضًا تقنيًا.
- صُحح تعارض ترجمة `checkout`: الإجابة التي تختزل «عملية الشراء» إلى الدفع فقط لم تعد تحصل على رصيد قبول.
- أصبحت خاتمة الباحث متكيفة مع مسار الجولة؛ رفض العقد أو الدخول بلا عمل لا يطلبان أدلة أو أعباء من وردية لم تحدث.
- أُصلح تباين بطاقة الانتقال إلى دور الباحث، وأصبحت شبكات النتائج والأطراف مرنة، وأزيل CSS قديم خاص بوسيط الدفع داخل خريطة السلطة.
- توسعت اختبارات الوصول لتغطي صفحة نهاية الوردية والتحقيق والتنقل بلوحة المفاتيح، وتوسعت اختبارات E2E لتغطي الرجوع من القرارات النهائية والاستراحة.
- أضيف `ECONOMY_MODEL_VERSION=2`، وأصبح الأرشيف يقارن النتائج فقط داخل الحالة ومسار النهاية ونموذج الدرجة والنموذج الاقتصادي نفسها.

## المسارات

`/scenario/`, `/onboarding/`, `/work/`, `/management/`, `/risk/`, `/dispute/`, `/payment/`, `/access/`, `/investigation/`, `/power/`, `/conclusion/`, `/result/`, `/rights/`.

هذه ملفات HTML مولدة ومطلوبة لـGitHub Pages؛ ليست نسخًا قديمة من منطق اللعبة. المصدر الوحيد للمسارات هو `assets/js/core/routes.js`. مولد الصفحات يكتشف أي shell مولد لم يعد موجودًا في route manifest ويبلغ عنه أو يحذفه.

## بنية الصيانة

- `assets/js/core/` — الحالة، التخزين، المسارات، واجهات مشتركة، ونموذج الدرجة.
- `assets/js/domain/` — قواعد العمل، الإدارة، المخاطر، الاعتراض، الدفع، الوصول والتحليل.
- `assets/js/data/` — السيناريوهات، الأطراف، مرجع السلطة، أدلة المهام، العينات وهندسة مشاهد البيانات.
- `assets/js/pages/` — واجهات مراحل اللعبة.
- `assets/css/` — التصميم والاستجابة.
- `tests/e2e/` — اختبارات Playwright والوصول.

بعد تغيير عنوان أو مسار أو إصدار:

```bash
node scripts/generate-pages.mjs
```

## التحقق قبل النشر

```bash
npm run check
npm run test:e2e
```

`npm run check` يغطي تطابق route manifest، البنية، ترحيل الحالة والتخزين، قواعد المجال، الاتساق بين الوحدات، وصحة JavaScript. اختبارات المتصفح تعمل على Chromium وWebKit لسطح المكتب والموبايل وتضم فحوص axe ومسارات الرجوع والحالات الطرفية.

## ملاحظة قانونية

المحاكاة أداة تدريبية لتحليل الوقائع وتوزيع وظائف السيطرة والأعباء، وليست حكمًا قانونيًا نهائيًا على توصيف علاقة العمل.
